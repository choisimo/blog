`680px`는 의도적인 선택입니다. 검증 중 같은 `70ch`라도 소제목과 문단에서 글자 크기·서체가 달라 실제 폭이 달라지는 문제가 발견되어, 동일한 물리적 최대 폭을 공유하도록 수정했습니다. 작은 화면에서는 부모 폭으로 줄어듭니다.

`center`, `wide`, `full`, `compact`, `aside-left`, `aside-right` 작성자 지정 값은 유지합니다. 다만 명시적인 별도 좌우 배치 컨테이너 없이 이웃한 이미지/코드라는 이유만으로 자동 2열로 묶지는 않습니다.

## 스타일 충돌을 처리한 방법

기사 규칙은 `src/styles/ui-reading.css`, 공유 스크롤 규칙은 `src/styles/ui-scrollbars.css`에서 관리합니다. 기존 `index.css`, `ui-pages.css`, `ui-adaptive.css`의 겹치는 기사/스크롤 정의를 정리했습니다. 공유 RICH 컨트롤 구현은 교체하지 않았습니다.

브라우저 검증에서 라이트 테마의 일반 모달 규칙이 이미지 뷰어의 어두운 배경을 덮는 것을 확인했습니다. 일반 모달 규칙에서 이미지 뷰어를 제외하여 해결했습니다. reduced-motion의 일반 반투명 배경 대체 규칙도 이미지 도구 영역을 덮지 않도록 조정했습니다.

표는 `display: table`을 유지하고 바깥 viewport만 가로로 스크롤합니다. 코드 하이라이터 내부의 스크롤을 제거하고 `article-code-region`이 담당합니다. 루트 `overflow-x: clip`은 지원되는 브라우저에서만 사용하며, 기존 hidden 동작은 비지원 브라우저의 대안으로 남깁니다.

## 유지한 경계

라우트, 번역 및 언어 선택의 처리 흐름, AI 문단 연결과 본문 메타데이터, Markdown 보안 정책, 코드/표 복사 처리, 동영상 렌더링 경로, 테마 토큰은 기존 구조를 사용합니다. 이미지 URL 검증을 우회하는 경로나 임시 API/stub는 프로덕션 코드에 추가하지 않았습니다.

백엔드·워커·배포 설정 및 원본 콘텐츠는 변경하지 않았습니다. 원본 1,706개 파일 중 15개를 수정했고, 나머지 1,691개는 바이트 단위로 동일합니다. 원본 파일 누락은 없습니다. 새 스타일·테스트·검증 스크립트·이 보고서는 추가 파일입니다.

**중요:** 제공된 스크린샷은 실제 저장소 CSS를 적용한 분리된 검증용 HTML입니다. React 앱 실행 화면이나 배포 화면이 아닙니다. 이 검증에서는 Tailwind `@apply`/utility 생성을 수행하지 않고, Radix의 실행 동작도 재현하지 않습니다. 따라서 CSS 검사의 통과를 전체 제품 테스트 통과로 해석하면 안 됩니다. 실제 앱 확인은 별도로 추가한 `test:e2e:reading`으로 수행해야 합니다.

의존성이 없는 상태에서 시도한 전체 소스 타입 분석도 React 등 모듈/타입이 누락되어 유효한 앱 타입 검사 결과를 만들지 못했습니다. 이를 성공으로 기록하지 않았습니다.

## 정상적인 개발 환경에서 확인하는 순서

아카이브를 기존 작업 폴더에 바로 덮어쓰기보다 새 디렉터리에 풀어 비교하는 것이 안전합니다. 현재 작업에 추가 커밋이나 수정이 있다면 패치를 먼저 `git apply --check`로 확인합니다. 검사 없이 강제로 덮어쓰거나 reset하지 않습니다.

```bash
cd blog/frontend
npm ci
npm run verify:reading
npm run type-check
npm run test:reading
npm run test:run
npm run build
```

실제 화면 회귀 검증은 빌드한 앱 서버를 먼저 실행한 뒤 진행합니다.

```bash
# 터미널 1
cd blog/frontend
npm run preview -- --host 127.0.0.1 --port 4173
```

```bash
# 터미널 2
cd blog/frontend
npx playwright install chromium
PLAYWRIGHT_BASE_URL=http://127.0.0.1:4173 npm run test:e2e:reading
```

E2E는 고정 Markdown/이미지만 해당 테스트의 요청으로 제공하며 외부/API 요청은 차단합니다. 프로덕션 소스에 mock을 연결하지 않습니다. 실제 번역·AI·댓글 API 연동 검증은 이 테스트 범위 밖입니다.

CSS 단독 검증 화면은 다음 명령으로 다시 만들 수 있습니다.

```bash
cd blog/frontend
node scripts/reading-verification/make-css-fixture.mjs reading-evidence/reading-css-fixture.html
# Python Playwright와 Chromium이 준비된 환경에서만 실행
python scripts/reading-verification/check_css_browser.py reading-evidence
```

`verify:reading`은 기본적으로 프로젝트의 TypeScript/PostCSS를 사용합니다. 외부 경로를 지정하는 `READING_TYPESCRIPT_PATH`, `READING_POSTCSS_PATH`는 이번처럼 패키지가 제한된 환경에서만 필요한 선택 사항입니다.

## 제공물과 되돌리기

전체 소스 압축파일은 수정한 파일과 원래 파일을 모두 포함하며 `.git`, `node_modules`, 일시적인 패키지 설치 결과는 포함하지 않습니다. 변경 패치는 첨부 원본을 기준으로 만들었습니다. 설치 환경과 기존 원격 Git 이력은 교체하지 않습니다.

적용 전 별도 브랜치를 만들고 검증한 뒤 결과를 받아들이십시오. 문제가 생기면 해당 리팩토링 커밋만 되돌리면 됩니다. 이번 변경에는 데이터 마이그레이션이나 되돌릴 수 없는 저장소 변경이 없습니다.

최종 상태는 **리팩토링이 반영된 소스 + 실행한 검증의 증거 + 아직 실행하지 못한 통합 검증을 재현할 테스트**입니다. 전체 앱 빌드 및 실제 서비스 동작은 설치 가능한 환경에서 확인한 뒤 배포해야 합니다.
